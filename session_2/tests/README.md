# Session 2 verification suite (instructor reference)

A runnable pytest suite that applies, to the Session 2 solution pipeline, the verification ideas taught in the slides. It is **instructor-only**: `sync_student.sh` removes this folder from the student branch, because students are meant to have Claude Code write their own tests during the exercise.

Use it to (a) check the solution pipeline, (b) show what a comprehensive suite looks like, and (c) check a student's expected values.

## Run

From the project root (`AIAgentsCourse/`):

```bash
python3 -m pytest session_2/tests                                              # run everything
python3 -m pytest session_2/tests --audit-report session_2/tests/audit_report.md   # and write the audit report
python3 session_2/tests/mutation_check.py                                      # "test the tests": inject bugs, confirm the suite fails
```

The suite runs the solution scripts in **temporary copies** of the project, so `session_2/output/` is never overwritten. It needs pandas, numpy, statsmodels and pytest.

## How it maps to the slides

| Slide | Where it is real |
|---|---|
| Layer 1: software tests | `test_01_software_layer.py` (smoke, unit, integration, end-to-end, regression, edge-case, negative) |
| Layer 2: research tests | `test_02` data integrity, `test_03` merge integrity, `test_04` variable construction, `test_05` sample accounting, `test_06` estimation and independent numerical checks, `test_07` outputs |
| Independent tests | `helpers.py`: the expected merge and the logistic regression are rebuilt by a different route (see below) |
| Trace samples end to end | `test_03_merge.py::test_trace_three_respondents_from_raw_files_to_merged_data` |
| Test the tests | `test_09_fault_injection.py`, `test_06_estimation.py` (planted answer), `mutation_check.py` |
| Requirements-to-tests matrix | `conftest.py` (`REQUIREMENTS` R0-R9); every test carries `@pytest.mark.requirement("Rn")` and the suite refuses to run a test without one |
| Audit report | `--audit-report` writes `audit_report.md`; `audit_report.md` is a generated example |
| Complete rebuild, repeatability | `test_08_reproducibility.py` |

## Why the tests are independent

Nothing in `helpers.py` calls the pipeline's analysis code. Expected values come from:

- the **merge**: the `csv` module and a dictionary lookup (not `pandas.merge`)
- the **estimates**: a hand-written iteratively reweighted least squares in numpy (not statsmodels), with its own standard errors and p-values
- **closed-form identities**: in a model saturated in treatment, `logit(intercept)` equals the weighted control-group share computed straight from the raw CSV
- the **instructor answer key** and the **codebook**, for values verified separately

Where the pipeline's functions are tested directly (`stars`, `coef_str`, `fit_logit`), they are loaded without running the scripts (`helpers.load_functions_from_script`), because the solution scripts execute at import.

## Known issues the suite reports (strict expected failures)

These are real defects in `solution_estimate.py` found by the suite. They are recorded as `xfail(strict=True)`: the assertion is *not* weakened, and when the script is fixed the test will start passing and pytest will flag the stale marker.

- Summary-table labels state ranges that contradict the table's own Min/Max columns and the codebook: Education `(1--5)` (data 1-4), Urban-rural `(1--5)` (data 1-3), Income quintile `(1--5)` (data 0-5), Left-right `(0--10)` (data -3 to 3).
- The FX dummy rows report N = 2,044, because `(fx_status == "current")` is false for the 2 respondents with missing `fx_status`, silently coding them as "not exposed". It should be 2,042.

## What the suite does not do

See "Not tested", "Needs your call" and "Not covered" in the generated audit report. In short: it does not test the Stata and R versions of the pipeline, does not reinstall dependencies from scratch, checks the interaction model only for N, and cannot say whether the identification strategy or the specification is valid.
